1.6 已实现的边界场景

场景处理方式
用户名不存在 / 密码错误统一提示"用户名或密码错误"
连续输错 5 次密码锁定账号 15 分钟
账号被禁用提示"账号已被禁用，请联系管理员"
Token 过期Axios 拦截器捕获 401，跳转登录页

密码强度不足前端 + 后端双重校验
新旧密码相同提示"新密码不能与旧密码相同"
未登录访问路由守卫拦截，跳转登录页
禁用自己前端 + 后端双重拦截，提示"不能禁用自己的账号"
学号格式校验纯数字，3-50 位
邮箱格式校验标准邮箱格式
角色权限拦截越权访问被拦截，跳转角色首页
页面刷新登录保持Token + 用户信息持久化到 localStorage

3.3 阶段 2 详细内容：文档上传与 LLM 解析

核心流程：

辅导员上传文档（PDF/Word）
    ↓
PyMuPDF/python-docx 解析 → 纯文本
    ↓
双轨并行处理：
    ├── 轨道一：LLM 提取结构化字段
    │   ├── 项目名称、截止时间、硬性门槛、互斥项
    │   ├── 材料清单、评选流程、联系方式
    │   └── 存入 policy_metadata 表
    │
    └── 轨道二：文本切片 + Embedding + pgvector 入库
        └── 为后续 RAG 问答准备数据
    ↓
辅导员进入预览页核对 → 确认发布

涉及的技术点：

  • PyMuPDF 解析 PDF 文本
  • python-docx 解析 Word 文本
  • LLM API 调用（DeepSeek/通义千问）进行结构化提取
  • 文本切片策略（chunk_size=512, overlap=64）
  • Embedding API + pgvector 向量化入库
  • 新增表：policies、policy_metadata、policy_chunks
